## Sensitivity: the 9,036-alert problem

The detectors asked one question — *is this unusual for this merchant?* — and
fired whenever the answer was yes. A HKD 150 transaction at a convenience store
can be a genuine four-sigma outlier and still be worthless to a launderer.

Statistical significance is not practical significance. Amount detectors now
require **both**: the z-score *and* an absolute materiality floor.

Deliberately **not** applied to count, velocity or timing signals. Small and
frequent is the shape of structuring, so smallness is not exculpatory there —
applying the floor everywhere would have blinded the detectors that catch
smurfing.

| Materiality floor | Alerts (synthetic set) |
|---|---|
| HKD 0 (disabled) | 18 |
| HKD 1,000 (default) | 17 |
| HKD 5,000 | 15 |

The synthetic merchants have large tickets, so the effect here is muted. On the
real data — where the noise was convenience-store outliers — it will be far
larger. **Not yet measured against the real portfolio.**

## Tunable thresholds

Moved out of code into the database: outlier z, moderate z, materiality floor,
maturity count and span, lag, window, plus **per-MCC overrides** so a jeweller's
lumpy tickets tolerate more volatility without blinding the grocer.

New **Tuning** tab with sliders. Each control states its trade-off — a slider
with no stated cost invites turning sensitivity down until the queue is empty,
which is not the same as having no risk.

Changes apply to the **next run**, never retroactively: existing alerts were
judged under the thresholds in force at the time, and rewriting that would break
the audit trail.

## Per-payment-method baselines

HKD 3,000 on Octopus is remarkable; the same on Visa is not. Pooled, the spread
is wide enough to swallow the Octopus case entirely — the rail that most needed
watching was the one the pooled view hid.

Each merchant now gets an amount baseline per `card_type`. A rail the merchant
barely uses comes back unusable rather than fitted, since two Alipay
transactions a month is not an Alipay pattern.

## Decision workflow

The decision was missing, and it is the product. Confirm/false buttons sit at
the **top** of the review page with mandatory reason codes.

| Verdict | Effect |
|---|---|
| **Confirm alert** | Opens a case; the day is quarantined from every future baseline so the system stops absorbing its own findings |
| **False alert** | Data stays in the baseline — cleared means legitimate, and removing it would teach the system that normal trading is abnormal |

Either way the alert leaves the open queue. Deciding twice returns 409: the
first decision is the audit trail.

## Case follow-through

Controlled stage vocabulary — contacted, documents requested/received/verified,
no response, escalated to legal, STR filed, cleared, confirmed illicit,
offboarded. Stages **append**; the timeline is the record, and overwriting a
status would erase how the case got there.

Open cases untouched for a week surface as **stale** and sort first.

## Review flow

Landing on all twelve indicators was the complaint. The page now opens on the
one that **raised this alert**, marked as such, and one selector drives all
three tabs so switching tab keeps the analyst on the same indicator. Widening to
"all" reveals everything that fired for the merchant.

**Statistical proof is gated on relevance**, each view stating what it is
evidence for:

| View | Addresses | Silent on |
|---|---|---|
| Amount table | the amount comparisons | timing, volume |
| Peer box plot | merchant-vs-peer level only | timing, single transactions |
| Hours density | timing only | amounts |

Showing all three for every alert implied each was evidence for the alert at
hand — which is how a KDE plot ends up beside an amount anomaly.

## Pagination

20 per page, with type counts computed server-side across the whole queue.
Counting only the visible page would make the filter chips lie.

## Wording and tooltips

Unified on **transaction** and **alert**. "Case" now means only a confirmed
alert being followed up. Tooltips on tabs, filter chips and every threshold.
